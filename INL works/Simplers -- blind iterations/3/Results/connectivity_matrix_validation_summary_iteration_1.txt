Connectivity matrix validation summary - Document 3, Iteration 1

Ground truth normalization:
The GT file is an edge list, so it was normalized into an undirected set of component-to-component edges before validation. The extracted CSV files were adjacency matrices and were normalized into the same undirected edge-set format. Diego/Jennifer round matrix files and final_connectivity_matrix.csv were evaluated.

GT after normalization: 60 undirected edges across 55 component names.

Main reason the scores were not perfect:
The non-perfect scores were caused by connectivity/edge discovery errors, not by component naming. All GT component names were present exactly in every evaluated matrix, and there were no extra non-GT component names. The score drop came from a mix of missing GT edges and a few incorrect extra edges between valid GT nodes.

- BUS-120AC-A -- RELAY-27A
- BUS-120AC-B -- RELAY-27B
- RELAY-86A -- RPS-PNL-A
- RELAY-86B -- RPS-PNL-B

- RELAY-27A -- RPS-PNL-A
- RELAY-27B -- RPS-PNL-B

What was not responsible:
- Component names were not wrong or close-but-imperfect; every GT component name appeared exactly.
- No GT components were missing from the extracted matrices.
- No extra intermediate/non-GT nodes were inserted into the extracted matrices.
- No false negatives were recoverable as a two-hop path through an intermediate node.

Examples causing the drop:
- Diego Round 1 added incorrect direct edges such as RELAY-86A -- RPS-PNL-A and BUS-120AC-A -- RELAY-27A while missing the GT breaker/relay links CB-103 -- RELAY-86A and CB-201A -- RELAY-27A.
- Jennifer Round 1, Diego Round 2, Jennifer Round 2, and the final connectivity matrix each had only one FP, BUS-120AC-B -- RELAY-27B, but missed a larger set of control/relay-related GT edges including CB-103 -- RELAY-86A, CB-104 -- RELAY-86B, RELAY-27A -- RPS-PNL-A, and RELAY-27B -- RPS-PNL-B.
- GND-STA -- TR-201A was also missed in every evaluated matrix.
